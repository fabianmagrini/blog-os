# Voice Guide

## Audience

Experienced software engineers, architects, and engineering leaders. See
`config/audience.md` for detail.

## Prefer

- direct language
- strong but defensible opinions
- concrete examples
- architecture diagrams
- trade-off analysis
- implementation recommendations
- short paragraphs
- precise technical terminology
- pragmatic conclusions

## Common patterns

Prefer structures such as:

```text
Problem
→ Observation
→ Thesis
→ Model
→ Example
→ Trade-offs
→ Recommendation
```

## Avoid

- excessive hype
- marketing language
- generic AI optimism
- unnecessarily long introductions
- repeated conclusions
- fake anecdotes
- fake personal experience
- excessive bullet lists
- overuse of rhetorical questions

## Avoid phrases such as

- "In today's rapidly evolving landscape"
- "Let's dive in"
- "It is important to note"
- "Game-changing"
- "Revolutionary"
- "Unlock the power of"
- "This paradigm shift"
- "The possibilities are endless"

## Notes for the Voice Editor

The Voice Editor (`agents/voice-editor.md`) may change phrasing, sentence
structure, pacing, paragraph structure, transitions, and verbosity. It must
not change factual meaning, the thesis, technical conclusions, evidence, or
citations.

## Evolving this guide

This guide should evolve based on published writing. After each article, the
Retrospective agent (`agents/retrospective.md`) should propose specific,
concrete edits here — e.g. a phrase that crept in and should be added to
"Avoid," or a structural pattern that worked well and should be added to
"Common patterns." Prefer small, evidence-based edits over rewriting this
document wholesale.
